# P1.2D Qt Blueprint v2 Restricted Editing Plan

> Execute with subagent-driven-development: one cohesive implementation task, independent specification/whole-branch review, primary integration and actual Windows acceptance. The user authorized implementation through PR delivery. Steps use checkboxes.

**Goal:** Edit only the three B2-supported field classes in Qt, preview through TypeScript, safely save to the selected v2 project, and reopen without losing untouched source bytes.

**Architecture:** Keep the existing v1 one-shot read protocol compatible; add version2 document load/preview/save operations around the existing Reader/Registry/B2/Store. Qt owns form state, document identity and asynchronous lifecycle, never Blueprint validation or JSON span rewriting. A disk baseline and canonical edit batch are retained separately from preview source; only a verified save advances the baseline.

**Tech stack:** Existing C++17/Qt6 Widgets/QProcess, TypeScript/Node24/Ajv/Vitest/CMake. No new dependency, server, plugin execution, Host or framework.

**Spec:** User P1.2D request; [B2 API](../../tools/schema-contracts/README.md#restricted-blueprint-document-edits), [Store guarantees](../../tools/schema-contracts/README.md#actual-write-guarantees), [v2 Draft](../architecture/blueprint-schema-v2.md), [roadmap](../project-roadmap.md). User scope is authoritative.

## Global Constraints

- Start at latest merged PR61 main `b45a8c9646994422d24ce9440deca4f7bfaf90f4`, isolated `feature/p1.2d-blueprint-v2-qt-editing`. Original checkouts untouched; no auto-merge, force push, Tag/Release changes or paid AI.
- Only projectName, KnownNode's existing explicitly declared direct scalar properties, and existing uniquely declared static port display names are editable. Node sourceIndex and port array position+ID identify targets. UnknownNode payload, locks, identities, unit/type/definition versions, edges, channels and driverBindings remain read-only.
- Reuse prepareBlueprintEdits and saveEditedBlueprintDocument as the only edit/save authorities. No whole-document JSON.stringify or Qt reserialization for saving. A narrow shared target-eligibility helper may be extracted inside B2 for UI projection, preserving existing public behavior/tests; do not duplicate its authorization logic in Qt or use successful no-op edits to discover fields.
- Every protocol/result retains canGenerate:false. Legacy v1/Runtime v2, machine Schemas, Qt ProjectStore, generation/Candidate/manifest and existing file protections stay unchanged. No v2 SaveAs/create, layout persistence, dynamic ports, plugin execution, Core IR or target generation.
- B1 standalone-directory policy is not weakened: a writable project contains only blueprint.json. Original P1.2C browsing of other structurally valid v2 files must remain possible, but without a Store-approved baseline it is explicitly read-only with a reason. The repository demo (README/trust bundle beside source) is copied to a separate directory for editing; trust declarations remain independently selected outside that directory.
- Preserve exact base source text/hash, independent trusted metadata, preview and pending operations. Unknown fields, Unicode escapes, CRLF and opaque payload outside authorized scalar spans remain byte-identical. No automatic repair, migration, conflict overwrite or plugin upgrade.
- Saving is single-flight. During save reject switch/open/new/close, configuration changes, another save and preview; do not blindly cancel an in-flight writer. Process timeout/crash/malformed or missing reply after dispatch means outcome unknown, not not-written. Retain draft and old baseline, block another save until explicit successful reload/inspection. Respect Store committed-unverified and cleanup diagnostics; no silent retry or rollback.
- Visible labels, keyboard access, translated errors and light/dark compatibility. Pending operations show state; errors retain input and identify the failed field/location. Read-only snapshots remain selectable.

## Interfaces and ownership

- Preserve handleReaderRequest(input):ReaderReply and protocolVersion1 read requests. Add `handleBlueprintDocumentRequest(input:unknown):Promise<BlueprintDocumentReply>` in `tools/schema-contracts/blueprint-document-protocol.ts`; compiled CLI dispatches/awaits the correct version. Version2 request has requestId, operation `load|preview|save`, independent registry declarations and operation-specific payload. Load takes an explicit absolute directory; preview takes baseline sourceText plus edits; save takes directory, baseline sourceText, expectedSha256 and edits. Reject unsupported operations and malformed envelopes. No arbitrary filename/command or unrequested Store mode.
- Version2 replies echo version/requestId/operation and wrap the existing load/preparation/save result, plus readResult and declarative edit-target metadata where available. Only Store loaded/saved results supply a usable SHA-256. Export exact DTO types, including writeState; Qt checks correlation and transport/result shape, not Blueprint semantics. Retain source8MiB/message32MiB limits and credential-filtered environment; enforce the source bound before file-backed load where feasible, and never truncate after a successful write while reporting ordinary failure.
- Edit metadata enumerates current KnownNode targets and existing scalar values with sourceIndex and static port position/ID. It is a form hint, not an authorization token: preview/save reconstruct the Registry and call B2 again. Property replacements must preserve finite-number and negative-zero semantics: use a scalar literal string at the new wire boundary when Qt JSON number serialization would lose information, decoding only that literal in TS before calling B2. This is not document reserialization or a general JSON editor.
- Extend BlueprintV2Reader with typed load/preview/save entry points and operation-aware bounded process handling. Existing read/cancel behavior remains for reads/previews; save cancellation/loss is explicitly uncertain. CMake stages the new production TS dependency closure without downloading anything.
- MainWindow retains baseline source/hash/registry, target directory, canonical pending edits, preview result and epoch. Repeated changes to the same target replace a pending edit, not duplicate it; reverting to original value removes it. Empty batch restores the original Reader snapshot without fabricating a B2 edit. Preview failure never updates the accepted canvas or drops form input. Successful preview refreshes names/ports/properties/diagnostics and dirty title; no file I/O.
- Use an explicit **Edit v2 values…** dialog from the v2 view, with projectName and the selected node's TS-declared scalar/static-port targets. UnknownNode exposes no internal editing controls. Property values may use clearly labelled JSON scalar literals (examples for strings/bool/number/null); reject arrays/objects via TS. **Apply preview (not saved)** validates the complete candidate batch; Cancel leaves the accepted preview unchanged. Keep the existing properties snapshot/diagnostics panels.
- File Save/Ctrl+S dispatches the B2 save against the original disk baseline and complete batch. Only verified save replaces baseline/clears dirty and refreshes the Reader/diagnostics. Saving/reopening again works. Other v2 mutating/generation/build/export actions remain blocked; Schema1 Save retains its original path.
- V2 dirty transitions use Save/Discard/Cancel. Failed target load must not discard the current draft; validate the target before committing a transition. An async Save choice cannot be treated as synchronous success: resume the requested transition only after verified completion with the captured epoch/intent still valid. Close ignores its first event while saving and closes after verified save; failure keeps the window/draft. Do not turn a failed or stale save into a successful switch. Existing Schema1 blueprint/source prompts remain intact.
- One worker owns TS/Qt/CMake/tests/translations and any small demo changes. Primary owns this plan, README, usage/API/architecture/roadmap/progress prose, Git, independent review and physical Windows acceptance. No concurrent edits of shared files; worker creates no subagents and performs no Git mutations/remotes.

## Review Focus

1. Writer reply is lost after rename: GUI must report unknown commit, retain draft and require reload, not retry or claim old file survived. Test timeout/crash/malformed reply and Store committed-unverified explicitly.
2. Loaded source/hash, directory, independent descriptor state and epoch must not be mixed across projects, nodes, modal events or stale replies. Test switched selection, delayed previews/saves and dirty Save/Discard/Cancel.
3. Duplicate IDs, escaped property names and opaque fragments must not target the wrong array record or be reserialized. Test sourceIndex, static port index/ID, CRLF/Unicode/opaque exact bytes and batches.
4. Known definition with bad original property is still editable for repair; Unknown/untrusted locks never gain edit authority. Test invalid scalar value rejection, nested/undeclared read-only and no-op/reset behavior.
5. Unsafe/generated/v1 directories and external hash changes must fail without modifying originals. Preserve old read-only browsing, distinguish policy-only read-only from true load failure, and keep legacy generation permissions closed in v2.
