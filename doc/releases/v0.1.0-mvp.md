# v0.1.0-mvp — Release Notes / 发布说明

发布准备文档。目标为源码 Pre-release；收尾 PR 人工合并、最终 `main` 验证通过且版本 Tag 不存在时才发布。最终提交由 annotated Tag 指定。本版本不附带二进制或 Windows 安装包。

## 中文

Qt Blueprint Generator 的原 MVP 提供六类蓝图节点、连线和结构化属性编辑，支持撤销/重做以及蓝图语义和画布布局持久化。AI 按模块生成候选代码，经人工差异审核、接受或拒绝后进入 Qt/CMake 工程；ExternalCode 以黑盒接口契约和 SHA-256 校验导入，Workspace Editor 支持源码浏览、安全编辑和未保存提示。工程可构建并完整导出，界面支持中英文和明暗主题。

原 MVP 14 项验收标准已通过，PR #48 已修复 Candidate Review 中 Unicode 草稿及差异显示问题。发布收尾全新完整构建成功，最终 CTest 30/30 通过；范围及平台限制见 [MVP 验收报告](../mvp-acceptance-report.md)。真实 DeepSeek `deepseek-flash` 验收使用一次请求、一个简单 LogicModule，经生产客户端和离屏 Candidate Review 控件完成生成、三个文件原字节接受、工作区构建/CTest 2/2、导出及导出工程独立构建/CTest 2/2；文件哈希和受保护文件检查通过。

已知限制：一次简单模块通过不保证所有 AI 输出均可编译或满足业务要求。候选接受后仍应构建和测试；跨重启重新打开历史候选批次尚未提供。生成应用入口仍是脚手架占位窗口，Runtime Assembly、行级 Code Review 和 AI 返工尚未实现。原生目录选择、实际屏幕缩放与视觉效果仍需人工验收；Windows 大小写别名 GUI fixture 因文件系统限制跳过，底层保护测试通过。

下一阶段按 [项目路线](../project-roadmap.md) 推进可运行原型生成，由确定性生成器完成应用入口和模块装配，再建设行级评审与人工确认的 AI 返工闭环。本次发布收尾不实施这些功能。

## English

The original Qt Blueprint Generator MVP includes six blueprint node types, directed connections, structured properties, undo/redo, and persistence of blueprint semantics and canvas layout. AI generates module candidates for human diff review and explicit accept/reject. ExternalCode imports remain black boxes with interface contracts and SHA-256 verification. The Workspace Editor provides source browsing, safe editing, and unsaved-change prompts. Qt/CMake projects can be built and exported; the UI supports English, Simplified Chinese, and light/dark themes.

All 14 original MVP acceptance criteria have passed. PR #48 fixes Unicode preservation and diff highlighting in Candidate Review. A fresh full release-finalization build succeeded and CTest passed 30/30; scope and platform limitations are recorded in the [MVP acceptance report](../mvp-acceptance-report.md). A real DeepSeek `deepseek-flash` check used one request and one simple LogicModule through the production client and offscreen Candidate Review controls: three generated files were accepted without byte changes, the workspace built and passed CTest 2/2, and the exported project independently built and passed CTest 2/2. File hashes and protected files were verified.

Known limits: one successful module does not guarantee that every AI response will compile or satisfy business requirements. Build and test accepted candidates. Reopening historical candidate batches after restarting is not yet available. The generated application entry point remains a scaffold placeholder; Runtime Assembly, line-level Code Review, and AI rework are not implemented. Native directory dialogs, physical display scaling, and appearance still need human checks. One Windows case-alias GUI fixture is skipped because of filesystem limitations; backend protection tests pass.

The next phase follows the [project roadmap](../project-roadmap.md): deterministic application entry-point and module assembly for runnable prototypes, followed by line-level review and an AI rework loop with explicit human acceptance. This release-finalization task does not implement those stages. This is a source-only Pre-release; no binaries or Windows installer are attached.
